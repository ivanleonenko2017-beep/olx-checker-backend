## Підтверджені проблеми пошуку до PR #35

1. OLX parser зупиняв додавання карток після перших 30. Це відбувалося до перевірки міста й інших критеріїв.
2. Parser також збирав картки через усі посилання оголошень у DOM, включно з вкладеними/додатковими блоками. У production-логах було видно змішані міста.
3. У production Smart Search не мав окремого строгого критерію моделі iPhone. Тому базова модель могла збігатися з Plus/Pro/Pro Max.
4. Перевірка міста використовувала substring у повному тексті картки. Це могло прийняти картку, де назва міста згадана не як місце розташування.
5. Parser обробляв одну сторінку видачі; наступні сторінки не запитувалися.
6. Parsed model constraint не зберігався гарантовано в усіх сценаріях створення фільтра, а worker не відновлював його для старих збережених запитів.

### Production-діагностика, яка була доступна до змін

Для одного з попередніх пошуків у логах було зафіксовано приблизно 30 розібраних карток, 5 карток після перевірки міста та 4 кінцеві результати. Це підтверджує втрати до/під час фільтрації, але **не підтверджує**, що на OLX було рівно 16 оголошень, які мали відповідати строгим умовам.

## Що змінено в PR #35

- Додано \`modelTerm\` для точного покоління та модифікації iPhone. Базова модель не приймає Plus/Pro/Pro Max/Max/Mini.
- Додано shorthand для пам’яті, зокрема \`iPhone 15 Pro Max 256\`.
- Відсіюються оголошення-покупці та очевидні оголошення аксесуарів під час пошуку телефону.
- Parsed model constraint зберігається під час створення фільтра; worker повторно розбирає старі збережені текстові запити.
- Межу карток на сторінку піднято з 30 до 200; parser вимагає валідне OLX-посилання та перевіряє домен.
- Місто порівнюється з фактичним location label, а не довільним substring у тексті картки. Якщо місто не підтверджене, картка не видається як місцева.
- Додано обмежену пагінацію для міських текстових пошуків: за замовчуванням 2 сторінки, конфігураційна межа — до 3; картки дедуплікуються за canonical URL.
- Середня ринкова ціна рахується лише за відповідними місцевими оголошеннями з підтвердженою пам’яттю.
- Background worker застосовує той самий fallback для невідомої пам’яті, що й Smart Search. Такі оголошення позначаються як «обсяг пам’яті не підтверджено» у Mini App і Telegram-повідомленнях.
- Додано escaping для неперевіреного тексту оголошень у Telegram HTML та Mini App; посилання й джерела зображень перевіряються перед вставленням у розмітку.
- Premium test bypass дозволений лише для локального \`NODE_ENV=test\`, не для Render.

## База даних і безпека

- Перевірено 12 таблиць public schema. RLS увімкнений; ролі \`anon\` та \`authenticated\` не мають CRUD-доступу до цих таблиць. Робота застосунку йде через серверний ключ.
- Політик RLS для клієнтських ролей немає. Це узгоджується з відсутністю прямих прав доступу для \`anon\`/\`authenticated\`; доступ до даних залишається серверним.

## Що не вдалося підтвердити

1. **Live OLX pagination.** Діагностичний запит із GitHub Actions runner отримав HTTP 403 від OLX/AWS edge. Це не доводить, що Render також заблокований: попередні Render-логи містили повний HTML відповіді OLX. Фактичну роботу сторінки 2 треба перевірити з Render після деплою.
2. Не вдалося зберегти реальний HTML fixture з GitHub runner через 403. Поточні тести перевіряють розбір критеріїв та pagination helper, але не є тестом на повній live HTML-сторінці OLX.
3. Не проводилися реальні платежі, Telegram-розсилки або дії від імені інших користувачів.
4. Не перевірено production-значення env vars, оскільки вони не потрібні для читання та не повинні потрапляти в звіт.

## Виявлені задачі поза PR #35

На момент першого пошукового PR ці задачі ще були відкриті. Їх виправлення підготовлені в PR #36:

- Атомарне нарахування реферального бонусу, збереження pending referral при тимчасовій помилці та повторна спроба на наступному \`/start\`.
- Міжпроцесний lock на кожен фільтр із lease та автоматичним звільненням/закінченням lease.

Залишаються поза автоматичним виправленням:

- Юридичні тексти в застосунку позначені як проєкти. Дані про юридичну особу/постачальника та остаточна правова перевірка потребують власника; їх не можна вигадувати.

- Live OLX pagination і фактична кількість результатів ще потребують контрольного пошуку після production-деплою.

Після цього перевірити Render logs: кількість карток page 1/page 2, кількість унікальних оголошень, підтверджені міста, точну модель, пам’ять і фінальну кількість. Не порівнювати результат із фіксованим числом: кожне оголошення має відповідати реальним критеріям користувача.


## Додаткове P1 hardening (PR #36)

- Додано атомарну RPC-операцію для реферального бонусу: блокування рядків користувачів у стабільному порядку, унікальна атрибуція invitee, продовження Premium від більшої з поточної дати та чинного \`premium_until\`. Код реєструє referrer тільки при першому \`/start\`; якщо RPC тимчасово не спрацювала, pending attribution зберігається для повторної спроби.
- Додано міжпроцесний lease-lock на кожен filter. Перевірено послідовно: перший worker отримує lock, другий не отримує; чужий owner не може звільнити lock; правильний owner звільняє його. Після тесту таблиця lock-ів порожня.
- Додано \`telegram_blocked_at\`: після HTTP 403 користувач позначається заблокованим, worker не повторює відправлення; наступний вхідний \`/start\` очищає позначку.
- Додано обмежені повторні спроби Telegram при HTTP 429 із використанням \`retry_after\`.
- Worker тепер обмежує кількість оброблюваних фільтрів для всіх планів за \`filterLimit\` (Free/Trial/Premium), а не лише Free. Список фільтрів у Mini App сортується так само, як у worker; фільтри понад ліміт залишаються збереженими й явно показуються як призупинені.
- Додано \`package-lock.json\` та вимогу Node \`>=20\` для відтворюваної інсталяції залежностей.

### P1 migration

Додані колонки в \`users\`, таблиця \`filter_processing_locks\` та три service-role-only RPC-функції. Міграцію застосовано до того самого Supabase project. Користувацькі рядки не змінювалися; тестовий lock створювався і видалявся, залишкова кількість lock-рядків — 0. Успішне нарахування Premium реальному користувачу не тестувалося, щоб не змінювати його тариф.
