# ЗНАЙДЕНО — план завершення публічного релізу
Дата: 28.10.2026
Гілка підготовки: `release/stars-only-legal-alignment-2026-10-28`

## Поточне рішення
**NO-GO для публічного комерційного запуску до закриття юридичних та платіжних блокерів.** Цей документ — робочий release gate, не юридичний висновок.

## Зміни в цій гілці
- У Mini App прибрано видимі кнопки Monobank-банки та ручного підтвердження такого переказу.
- Сервер більше не повертає посилання на Monobank-банку для Mini App; старий endpoint ручного claim відповідає 410.
- Залишено Telegram Stars як платіжний метод усередині Telegram: 180 ⭐ за 30 днів, одноразово, без автоматичного поновлення.
- Повідомлення платіжної підтримки приведено до контакту `@esqide`.
- Оферта, умови оплати/повернення та політика конфіденційності синхронізуються з поточним платіжним сценарієм. Вони все ще є проєктами, оскільки реквізити постачальника й фактичні правила обробки даних не підтверджені.

## Блокери до комерційного запуску
- [ ] Визначити та документально підтвердити законну модель постачальника послуг. Власник повідомив, що наразі працює як фізична особа без ФОП; це питання не можна закрити лише текстом оферти.
- [ ] Підтвердити повне ім'я/найменування, правовий статус, реєстраційні/податкові дані, адресу для офіційних звернень та публічний контакт. Не вставляти вигадані дані.
- [ ] Отримати бухгалтерське/юридичне підтвердження оподаткування доходу від цифрової послуги та необхідних реєстрацій.
- [ ] З'ясувати, які документи про оплату/фіскалізацію потрібні для кожного сценарію. Не вважати переказ на банку чи Telegram Stars автоматичним підтвердженням податкової відповідності.
- [ ] Перевірити оферту, повернення, споживчі права й політику приватності з юристом.
- [ ] Визначити фактичні строки зберігання для профілю, фільтрів, платіжних записів, логів і резервних копій та реалізувати видалення/анонімізацію там, де це належить.
- [ ] Перевірити, як користувач може підтвердити згоду з умовами до покупки та як система фіксує версію умов і час прийняття. Не покладатися лише на наявність посилання в інтерфейсі.
- [ ] Перевірити реальне повернення Telegram Stars через Bot API та визначити, хто й як його запускає; /paysupport має працювати.
- [ ] Провести реальну тестову покупку в Telegram, перевірити successful_payment, повторну доставку webhook, захист від подвійної активації, строк Premium і відновлення після помилки БД.
- [ ] Переконатися, що в Mini App немає стороннього способу оплати цифрового Premium, оскільки Telegram вимагає Stars для цифрових товарів/послуг усередині Telegram.

## Технічний smoke-test перед релізом
- [ ] `/start`, `/terms`, `/paysupport`, `/admin` у production-боті.
- [ ] Відкриття Mini App і перевірка профілю, тарифу та лімітів.
- [ ] Створення/видалення фільтра; перевірка, що користувач не може читати/видаляти чужі фільтри.
- [ ] Перевірка нових оголошень, дедуплікації, фото та fallback-зображення, опису оголошення.
- [ ] Перевірка реферальної логіки та адмін-розсилки на контрольному тестовому акаунті.
- [ ] Перевірка production Render logs і Supabase errors після тестів.
- [ ] Підтвердження, що секрети зберігаються лише в Render Environment, а service-role key не потрапив у фронтенд.
- [ ] Після тестів створити release tag/notes і зафіксувати commit, який реально розгорнуто.

## Висновок
Ця гілка виправляє суперечність у способах оплати всередині Telegram, але сама по собі не дає підстав оголошувати юридичну готовність. Публічний комерційний запуск можливий лише після закриття обов'язкових пунктів вище та успішного end-to-end тесту.
