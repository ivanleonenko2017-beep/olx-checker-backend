# Знайдено — checklist для завершення юридичних документів

Цей файл — робочий checklist, не юридична консультація і не затверджена публічна політика. Не публікувати як остаточні умови до заповнення власником і перевірки юристом.

## Категорії даних, видимі у схемі Supabase

- Telegram ID користувача та ім'я профілю (users.telegram_id, users.first_name).
- Стан тарифу, дата початку Trial, дата завершення Premium, адміністративний і технічний стан Telegram-доставки.
- Відкладений реферальний ID та дата реферальної атрибуції.
- Текст фільтрів, місто, стан товару, цінові межі та критерії пошуку (filters).
- Посилання на вже оброблені оголошення (seen_ads).
- Історія спостережуваних цін (ad_price_history).
- Реферальні зв'язки та журнали рефералів (referrals, referral_logs).
- Платіжні події/рахунки (payments, star_payments, monobank_payments).
- Донати/спонсорські внески (sponsor_donations) та стан синхронізації банки (mono_jar_sync_state).
- Денне використання пошуку (user_daily_usage).
- Технічні блокування обробки фільтрів (filter_processing_locks).

## Системи та передавання даних

Підтверджені компоненти: Telegram (бот, Mini App, повідомлення), Render (backend, worker, журнали), Supabase (PostgreSQL), OLX (зовнішнє джерело оголошень). Monobank і Telegram Stars присутні в коді/схемі; фактичні production-перемикачі треба звірити з налаштуваннями Render.

Не стверджувати, що дані «нікому не передаються». Перед запуском звірити актуальні умови Telegram, Render, Supabase, OLX та платіжних провайдерів.

## Обов'язково заповнити власнику

- [ ] Повне юридичне ім'я постачальника сервісу.
- [ ] Статус і реєстраційні дані ФОП/юридичної особи (якщо застосовно).
- [ ] Юридична адреса / адреса для звернень.
- [ ] Країна та юрисдикція договору.
- [ ] Контактний e-mail для запитів про дані, скарг і підтримки.
- [ ] Контакт для питань оплати та повернення коштів.
- [ ] Фактичні строки зберігання кожної категорії даних.
- [ ] Процедура та строк видалення даних користувача.
- [ ] Умови скасування Premium і повернення коштів.
- [ ] Чи є автоматичне поновлення або лише фіксований строк.
- [ ] Які платіжні механізми реально увімкнені в production.
- [ ] Чи залучаються додаткові аналітичні/AI-провайдери у production.

## Перевірки публічних документів

- [ ] Використовується лише бренд «Знайдено».
- [ ] Опис тарифів відповідає фактичному коду.
- [ ] Пояснено, які дані збираються, для чого, де обробляються та кому передаються.
- [ ] Є реальна процедура запиту на доступ/виправлення/видалення даних.
- [ ] Є умови оплати, строку Premium, скасування та повернення.
- [ ] Є контакт постачальника.
- [ ] Є заява, що «Знайдено» не пов'язаний з OLX, не є продуктом OLX і не представляє OLX.
- [ ] Немає гарантій повноти оголошень або безперервної доступності зовнішнього джерела.
- [ ] Немає неправдивої заяви про відсутність передавання даних третім сторонам.
- [ ] Немає вигаданих реквізитів або заяви про юридичне затвердження без перевірки.

## Строки зберігання та видалення

Точні строки зберігання не підтверджені. У схемі не виявлено єдиної політики автоматичного видалення для всіх категорій. Не вказувати вигадані строки. Власник має визначити строки та реалізувати відповідні механізми видалення/анонімізації.

Публічні документи не можна позначати як «затверджені» або «перевірені юристом», поки власник не заповнив обов'язкові поля і юрист не перевірив фінальний текст.
